# 微信自动回复模块重构规范 (WeChat Auto-Reply Module Refactor Spec)

## Why
当前系统的通讯配置页面将所有配置混合在单一页面中，自动回复机制的后台持续运行、消息监听、规则匹配与组装逻辑尚未完全独立并形成闭环。为了提高系统的可维护性与扩展性，降低业务耦合，需要将整个微信自动回复相关功能（含前端交互、业务逻辑、样式及依赖资源）封装为零外部依赖、可热插拔的独立模块，并集成至“通讯配置”页面的“微信”子板块中。

## What Changes
- 将当前的通讯配置页面中的微信相关功能拆分为一个独立的前后端全栈模块。
- 在“通讯配置”页面左侧菜单新增“微信”入口，点击后动态加载微信自动回复模块。
- 模块加载后自动读取并回显现有的微信配置信息。
- 提供可视化的表单，支持对自动回复规则进行增删改查（CRUD），并实时生效。
- 实现微信自动回复的核心闭环：后台持续运行、消息监听、规则匹配、内容组装与发送。
- 配置变更通过统一的 API 接口持久化，并支持一键恢复默认设置。
- 提供严苛的性能、单元及端到端测试保障（单元测试≥90%、高并发低延迟）。
- 撰写 `CHANGELOG.md`，提供完整的部署指引与回滚方案。

## Impact
- 影响的模块: 通讯配置页面 (`CommunicationPage`)、微信集成后台逻辑 (`backend/api/routes/skills.py`、微信服务层)。
- 涉及的代码:
  - 前端：`frontend/src/features/chat/CommunicationPage.tsx` 及其子组件。
  - 后端：微信通讯相关的服务层和配置持久化接口。

## ADDED Requirements
### Requirement: 独立热插拔模块架构
系统必须提供一个解耦的微信自动回复模块架构。该模块需独立打包或懒加载，前端不依赖于主应用之外的状态，具备独立的内部路由或状态管理；后端具备独立的轮询任务与规则引擎。

#### Scenario: 动态加载微信配置子板块
- **WHEN** 用户在“通讯配置”页面左侧点击“微信”菜单项
- **THEN** 系统动态加载微信通讯模块，并立即从统一配置接口读取微信 iLink 的 Account ID、Token、自动回复状态等信息并回显。

### Requirement: 可视化自动回复规则管理
系统必须提供一套可视化表单，允许用户添加、编辑、删除自动回复规则（如关键词匹配、正则表达式匹配等）。规则保存后必须实时生效并持久化。

### Requirement: 高并发消息处理引擎
自动回复模块必须具备高效的消息监听和规则匹配能力。要求在 1000条/秒 的并发消息下，系统的处理与回复延迟 <200 ms。

## MODIFIED Requirements
### Requirement: 通讯配置页面结构
原有的单页平铺结构改为侧边子菜单结构。页面被划分为左侧菜单导航（如“全局”、“微信”等）与右侧内容展示区。

## REMOVED Requirements
### Requirement: 硬编码的微信通讯平铺表单
**Reason**: 混合所有通讯渠道在同一个页面会导致代码臃肿，难以维护和扩展新的通讯方式（如钉钉、飞书）。
**Migration**: 移除原本平铺在 `CommunicationPage` 中的所有微信特定表单项，迁移至新封装的微信模块子组件中。
