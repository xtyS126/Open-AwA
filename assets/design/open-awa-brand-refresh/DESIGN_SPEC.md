# Open-AwA 品牌图标与三端原生界面设计规范

## 1. 设计目标

本次设计只产出独立的品牌与界面设计资产，不直接替换网页、Android 或桌面端当前正在使用的资源，也不修改产品业务代码。

设计需要同时满足以下目标：

- 为 Open-AwA 建立一套从零设计、与原图无关的原创图标。
- 图标不表达字母、表情、人物、机器人、脑、信号或其他具体对象。
- 整体气质偏轻快可爱，但不幼稚，不依赖卡通脸或吉祥物建立亲和力。
- 网页、Android APP、桌面端共享品牌语言，同时分别遵循各自平台的布局、密度与交互习惯。
- 所有最终资产集中保存在 `assets/design/open-awa-brand-refresh/`，便于独立审查、回滚与后续选择性接入。

## 2. 品牌方向

### 2.1 核心气质

品牌气质采用“轻快、柔软、灵活、可靠”的组合。可爱感主要来自柔和渐变、圆润边缘、暖色点缀、留白和轻弹节奏，而不是具象角色。

### 2.2 视觉关键词

- 轻快：避免大面积沉重深色和高对比硬边。
- 可爱：圆润、柔软、微微膨胀的材质感。
- 清晰：小尺寸仍有稳定、完整、容易记住的轮廓。
- 原创：不复用旧图标的双 A、眼睛、笑脸或线稿结构。
- 克制：每个界面只保留一处主渐变和少量暖色焦点。

## 3. 原创抽象图标

### 3.1 构形

最终采用“A：软晶单元”。图标由三个独立层级组成：

1. 紫罗兰圆角底板，用于 APP 图标和桌面应用图标。
2. 奶油白到浅桃色的外部软晶轮廓，形成完整、稳定的主体剪影。
3. 紫罗兰内部软晶层与小型留白切口，用于建立深度和缩小后的视觉焦点。

该构形不赋予任何象征含义，不解释为花、星、字母、角色或设备。对外描述只使用“Open-AwA 抽象标记”或“软晶单元”。

### 3.2 与旧图标的隔离规则

- 不读取旧图标的几何比例作为构图依据。
- 不使用双 A、双眼、笑脸、连接弧线或左右镜像字母结构。
- 不在设计说明中建立新旧图标的形态映射。
- 最终验收时将新图标与旧图标并排检查，确认不存在可识别的继承关系。

### 3.3 图标网格

- 母版画布：1024 × 1024。
- 安全区：四周至少保留画布宽度的 14%。
- 底板圆角：画布宽度的 24%，同时提供圆形与无底板版本。
- 主体视觉占比：画布宽度的 66% 至 70%。
- 最小视觉间隙：在 32px 输出中不得小于 2px。
- 内部切口只在 32px 及以上版本保留；16px favicon 使用简化构形。

### 3.4 色彩

| 用途 | 色值 |
| --- | --- |
| 主紫罗兰 | `#7654FF` |
| 深紫罗兰 | `#5E3FD6` |
| 浅紫罗兰 | `#A678FF` |
| 暖桃色 | `#FFB18F` |
| 浅桃色 | `#FFD8C8` |
| 奶油白 | `#FFF9F5` |
| 淡薰衣草 | `#F3EDFF` |
| 主文字 | `#342B40` |
| 次文字 | `#786C82` |
| 边框 | `#E8E0EE` |

图标底板使用 `#7654FF` 到 `#A678FF` 的斜向渐变。主体使用 `#FFF9F5`、`#FFD8C8` 和极浅紫色的柔和过渡。小尺寸版本减少渐变停靠点，保证边缘清楚。

### 3.5 图标输出

最终应提供：

- 可编辑 SVG 母版。
- 无底板 SVG 标记。
- 1024、512、256、128、64、32、16px PNG。
- 网页 favicon SVG 与 16/32px PNG。
- Android 自适应图标前景与背景参考 SVG。
- 桌面端 PNG 与 Windows ICO 设计资产。
- 图标构造网格和安全区说明图。

## 4. 三端共享设计系统

### 4.1 共享内容

三端共享以下品牌基础：

- 抽象软晶图标。
- 紫罗兰、暖桃色、奶油白和淡薰衣草色板。
- 标题、正文、辅助文本三级清晰层级。
- 轻弹、短距离、低幅度的动效节奏。
- 柔和圆角与低对比边框。
- 成功、警告和错误状态继续保持语义清晰，不强制染成品牌紫色。

### 4.2 不共享的内容

以下内容不得跨端机械复用：

- 导航位置。
- 内容密度。
- 窗口控制。
- 触控目标尺寸。
- 鼠标悬停状态。
- 多窗格数量。
- 手机安全区与桌面可调整面板。

## 5. 网页端原生界面

### 5.1 定位

网页端是跨设备访问的响应式工作区，优先保证信息层级、浏览器可访问性和不同宽度下的连续体验。

### 5.2 桌面浏览器布局

- 顶部使用 48 至 56px 的全局栏，容纳品牌标记、搜索、连接状态和用户入口。
- 左侧主导航宽度约 232px，可收起为 68px 图标栏。
- 中央区域承载聊天、任务或业务页面，是唯一主滚动容器。
- 右侧上下文面板宽度约 280 至 320px，按页面需要出现，不作为永久空白列。
- 聊天输入框固定在中央内容区底部，不跨越上下文面板。

### 5.3 响应式规则

- 1440px 及以上：三栏完整布局。
- 1024px 至 1439px：右侧上下文面板改为抽屉或覆盖层。
- 768px 至 1023px：左侧导航收起，保留顶部全局栏。
- 767px 及以下：采用移动网页布局，但不伪装成原生 Android APP。

### 5.4 网页视觉

- 页面背景以奶油白和极浅紫灰为主。
- 主操作使用实心紫罗兰，次操作使用描边或浅紫背景。
- 大型渐变只用于欢迎区、空状态或关键概览卡，不铺满所有卡片。
- 常规卡片圆角 14 至 18px，输入框圆角 14 至 20px。
- 浏览器端必须保留明显的键盘焦点样式和足够文本对比度。

## 6. Android APP 原生界面

### 6.1 定位

Android APP 是服务器中心架构下的触控瘦客户端，界面遵循 Material 3 的边到边布局、触控目标、系统栏和返回行为。

### 6.2 导航

- 一级入口使用四项底部导航：对话、任务、工作台、我的。
- 低频功能进入工作台聚合页或抽屉，不在底部导航堆叠更多入口。
- 二级页面使用系统返回与顶部应用栏，不复制网页左侧栏。
- 大屏手机、折叠屏与平板可将底部导航升级为 Navigation Rail。

### 6.3 Android 视觉

- 使用系统字体和 Material 3 字号层级。
- 顶部与底部适配状态栏、手势区域和显示切口。
- 主要触控目标不小于 48dp。
- 主卡片圆角约 24dp，次级卡片约 16dp，输入框采用 20 至 28dp 的圆润容器。
- 欢迎卡可以使用淡紫到奶油白渐变，并用暖桃色作为单一强调点。
- 动效使用轻微缩放和短距离位移，避免持续漂浮、眩光或大幅弹跳。

### 6.4 Android 图标

- 自适应图标前景不得接触安全区边缘。
- 背景为纯色或极简渐变，不在背景层绘制细节。
- 单色图标版本使用完整外部软晶剪影，适配 Android 主题图标。

## 7. 桌面端原生界面

### 7.1 定位

桌面端是高密度、长时间运行的多任务工作台，强调鼠标与键盘效率、可调整面板、并行信息和原生窗口行为。

### 7.2 窗口结构

- 保留 Windows、macOS 与 Linux 对应的窗口控制位置和行为。
- 左侧 40 至 48px 活动栏用于工作区切换。
- 次级资源树宽度约 200 至 260px，可调整和隐藏。
- 中央工作区支持标签页，对话、任务、预览与终端可并行打开。
- 右侧检查器宽度约 280 至 340px，可调整和隐藏。
- 底部终端或日志面板按需展开，不永久占用主内容高度。

### 7.3 桌面交互

- 提供命令面板、全局搜索和完整键盘快捷键入口。
- 使用明确的悬停、选中、拖拽分隔线和右键菜单状态。
- 信息密度高于网页端，正文通常为 13 至 14px，但不得牺牲可读性。
- 多窗格只在任务需要时出现，空面板自动折叠。

### 7.4 桌面视觉

- 背景使用偏中性的浅紫灰，编辑区和主要内容区保持接近白色。
- 品牌渐变只用于活动状态、主按钮和少量身份元素。
- 标题栏、标签页和面板边界保持克制，避免把每个容器都做成悬浮卡片。
- 提供浅色设计稿；深色模式属于后续扩展，不混入本次交付范围。

## 8. 字体与图标语言

### 8.1 字体

- 网页端：`Inter`、`Segoe UI`、系统中文无衬线字体回退。
- Android：系统 Roboto 与系统中文字体。
- 桌面端：跟随操作系统 UI 字体；代码和终端使用等宽字体。
- 品牌名称使用标准字重文本，不另造装饰性字标。

### 8.2 功能图标

- 功能图标采用统一线性图标库，不从品牌标记拆分部件制作功能图标。
- 常规线宽保持一致，选中态通过容器、颜色或填充变化表达。
- 不使用表情符号代替产品图标。

## 10. 验收标准

### 10.1 图标

- 与旧图标并排时不存在双 A、眼睛、笑脸或连接弧线等可识别继承关系。
- 16px、32px、64px、256px 均能辨认完整主体轮廓。
- SVG 无外部字体、外链图片或滤镜依赖。
- PNG 尺寸、透明通道和色彩模式正确。
- Android 安全区、Windows ICO 多尺寸和网页 favicon 均可独立检查。

### 10.2 界面

- 三张概念稿的导航结构明显不同，能够一眼识别网页、Android 和桌面端。
- 三端仍能通过图标、颜色、圆角节奏与字体层级识别为同一品牌。
- 概念稿使用真实的 Open-AwA 功能名称，不填充无意义占位文本。
- 网页稿体现响应式边界；Android 稿体现系统栏与底部导航；桌面稿体现窗口控制、多窗格与终端。
- 所有设计稿无旧图标、无表情符号、无水印。

## 11. 范围边界

本次交付只创建设计资产与可编辑源文件，不执行以下操作：

- 不替换 `frontend/public/logo.svg`。
- 不修改 `frontend/src/shared/components/BrandMark/`。
- 不替换 Android `mipmap` 或自适应图标资源。
- 不替换 `desktop/resources/icons/`。
- 不修改产品页面、路由、状态管理或业务逻辑。
- 不执行 Git 提交或推送。

后续如需将设计接入产品，应作为单独实施任务，并分别验证网页构建与浏览器效果、Android 构建与模拟器效果、桌面端打包与窗口效果。
