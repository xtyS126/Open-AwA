# 实施与验收计划

## 1. 实施边界

本文件定义后续实现顺序和验收门槛。本次设计任务不修改产品代码、不执行路由迁移，也不删除现有页面。

## 2. 分阶段实施

### 阶段 1：统一语义与清单

1. 建立版本化导航清单和 schema。
2. 为 TypeScript 和 Kotlin 生成稳定 ID、路由和权限类型。
3. 建立规范路由、旧路由重定向和路由覆盖测试。
4. 将站点地图、文档和埋点事件切换到规范 ID。

完成标准：三端不再新增手写领域清单；所有现有功能都有唯一目标位置。

### 阶段 2：页面合并与旧页面淘汰

1. 合并工作区、编码和 Vibe Coding 为工作台。
2. 合并工作流、计划、子智能体、运行和讨论为自动化。
3. 合并技能/插件/角色的管理与发现视图。
4. 合并记忆与经验；合并账户与画像。
5. 将仪表盘、收件箱和用量迁入动态。
6. 将 IM、宠物和预算配置迁入设置。
7. 删除不再被规范路由引用的重复页面组件。

完成标准：任一能力在产品中只有一个管理入口，旧 URL 只重定向而不渲染旧组件。

### 阶段 3：Web 新外壳

1. 实现五域领域轨道和当前域子导航面板。
2. 实现响应式投影和全局搜索。
3. 删除 `mobileHidden` 和“完整侧栏塞进更多”的结构。
4. 为每个领域保存最后访问位置。

完成标准：四档宽度下没有重复入口，键盘和读屏选中态正确。

### 阶段 4：Electron 原生整合

1. 重建原生系统菜单，使用共享命令 ID。
2. 增加命令面板、通知深链和托盘快速任务。
3. 将窗口标题栏、连接状态和当前项目整合为桌面上下文栏。
4. 验证 Windows、macOS 和 Linux 的系统菜单差异。

完成标准：原生菜单与渲染层导航职责互补，不存在两套页面菜单。

### 阶段 5：Android 自适应外壳

1. 引入 Material 3 自适应窗口分类和 Navigation Suite。
2. 为五个领域建立独立 back stack。
3. 用二级 Tab/列表和三级详情替换长抽屉。
4. 对未达到发布门槛的功能执行成熟度门控。
5. 删除导航可达的占位 Screen。

完成标准：手机、横屏、平板均使用对应原生导航模式；返回行为符合层级规则。

### 阶段 6：兼容层退场

1. 持续两个稳定版本统计旧路由访问。
2. 更新外部文档、通知深链和保存的快捷方式。
3. 删除旧重定向和不再使用的路由类型。
4. 执行全仓旧路径与旧组件名扫描。

完成标准：内部和外部已知入口都使用规范路由，全仓不再生成旧 URL。

## 3. 功能验收清单

- 一级工作域严格等于 5 个：助手、工作台、自动化、资源库、动态。
- 账户和设置只能从全局头像或命令搜索进入，不出现在五域子导航中。
- 技能、插件、角色的“已安装 / 发现”是视图状态，不是独立产品页面。
- 工作台切换“项目 / 编辑 / Agents”时保留当前项目上下文。
- 自动化运行详情统一承载日志、产物、审批和协作。
- 知识资源统一承载短期、长期、经验和质量。
- IM 配置只出现在设置，IM 消息只出现在动态收件箱。
- Android 正式导航中不存在占位页面。
- Web 移动端、Android 手机均不再打开包含 20 余项的完整抽屉。
- Electron 托盘和原生菜单不复制完整页面树。

## 4. 自动化验证

### Web

- 导航清单 schema 和唯一 ID 测试。
- 规范路由、旧路由重定向和权限回退测试。
- 领域选中态、子导航选中态和深链恢复测试。
- 480、768、1024、1440 px 视觉回归。
- 键盘遍历、`aria-current`、焦点回退和 200% 字体缩放测试。

### Electron

- 系统菜单模板与命令 ID 快照测试。
- 托盘、全局快捷键、通知点击和路由跳转的 IPC 契约测试。
- 最小窗口、最大化、全屏和多显示器恢复测试。

### Android

- Compact、Medium、Expanded 三种窗口类 Compose UI 测试。
- 五个领域独立 back stack 测试。
- 深链、返回、旋转和进程重建测试。
- TalkBack、48 dp 触控目标和系统字体放大测试。
- MuMu 手机目标和至少一个平板/可调整尺寸模拟器验收。

### 跨端

- 同一 `navigation_id` 在三端映射到同一领域语义。
- 权限和功能开关在三端隐藏同一能力。
- 通知、保存的深链和跨端任务接力都打开规范路由。
- 旧路由兼容期内不产生重定向循环。

## 5. 失败回滚边界

- 导航清单升级必须带 `version`，客户端遇到未知版本时拒绝加载动态清单并记录结构化错误。
- 新旧路由不可同时渲染两套页面；回滚只能切换整个规范路由版本。
- 页面合并期间保留数据 API 契约，不以导航重构为由修改用户数据模型。
- 不删除数据库、会话、记忆、计费或插件数据；本方案只改变入口和页面组合。

## 6. 最终验收证据

实施完成后，交付报告必须同时包含：

1. 导航清单及其生成产物。
2. 旧路由映射和全仓旧路径扫描结果。
3. Web 构建、测试和四档浏览器截图。
4. Electron 菜单、托盘、快捷键和通知深链测试。
5. Android 手机与平板的 UI 树、截图和返回栈验证。
6. 五域功能覆盖矩阵，证明没有能力遗失，也没有重复规范入口。
