# Open-AwA 三端原生导航重构方案

日期：2026-08-09

决策：采用 A3——任务优先，直接淘汰重复页面与重复导航目的地。

范围：网页端、Electron 桌面端、Android 原生端的导航信息架构与嵌套方式。

## 结论

当前产品把“技术页面”和“用户任务”放在同一层级。网页端侧栏直接暴露约 22 个入口，桌面端在完整网页侧栏外又叠加 Electron 菜单与托盘，Android 再手工复制一份约 23 个目的地。部分功能已经在页面内部合并，但旧路由和独立入口仍然存在；部分 Android 页面还是占位或模拟数据，却与成熟能力拥有相同导航权重。

新方案只保留五个一级工作域：

1. **助手**：对话、会话历史和当前上下文。
2. **工作台**：项目、编辑器、Vibe Coding、终端和文件预览。
3. **自动化**：工作流、定时任务、运行记录、子智能体和运行内协作。
4. **资源库**：技能、插件、角色、记忆、经验和语音资源。
5. **动态**：概览、收件箱、用量与系统状态。

账户、设置、连接和管理功能不再占据一级导航，而是从头像菜单进入。三端共享同一棵领域树，但使用各平台的原生呈现方式：Web 使用“领域轨道 + 子导航面板”，桌面端使用“原生标题栏 + 领域轨道 + 命令面板”，Android 使用 Material 3 自适应的底栏、Navigation Rail 或永久抽屉。

## 关键约束

- 不允许三端继续各自维护一份手写导航清单。
- 一个能力只能有一个规范入口；“已安装 / 市场”必须是同一资源页面的视图状态，不得是两个一级页面。
- 页面详情、编辑器面板、执行记录和权限审批属于上下文层，不得升级为全局导航项。
- Android 未接入真实 Repository 的页面不得以可用功能的形式出现在正式导航中。
- Electron 原生菜单承担命令和窗口操作，不复制渲染层的整棵导航树。
- 旧路由只允许在迁移期做重定向，不再渲染旧页面；两个稳定版本后删除兼容重定向。

## 预期结果

- 一级入口从 20 余个收敛到 5 个，设置入口独立于主任务导航。
- Web、桌面、Android 的领域名称和层级一致，但交互符合各自平台习惯。
- 相关能力在同一工作台内完成，不再在多个页面之间来回跳转。
- 路由、导航、权限、功能成熟度和平台可用性由统一清单驱动。
- 新用户可以从“想完成什么”选择入口，熟练用户可以通过搜索、命令面板和深链直达。
