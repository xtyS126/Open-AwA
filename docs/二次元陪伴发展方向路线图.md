## 一、产品愿景与定位

### 1.1 一句话定位

**Open-AwA = OpenClaw 级别的 AI Agent 能力 + 二次元陪伴的情感体验**

### 1.2 目标用户画像

| 用户类型 | 核心需求 | 使用场景 |
|---------|---------|---------|
| ACG 爱好者 | 与喜欢的二次元角色互动聊天 | 日常陪伴、情感倾诉、角色扮演 |
| 孤独感人群 | 有"人"陪伴、有人倾听 | 深夜聊天、心情低落时倾诉 |
| 技术玩家 | 定制自己的 AI 伴侣 | 自定义角色卡、训练专属人格 |
| 内容创作者 | 与 AI 角色共创内容 | 角色对话灵感、故事创作辅助 |

### 1.3 核心差异化

| 维度 | 通用 AI Agent（OpenClaw 等） | Open-AwA 二次元陪伴 |
|------|---------------------------|-------------------|
| 核心价值 | 任务执行效率 | 情感陪伴体验 |
| 交互方式 | 指令式（"帮我做 X"） | 对话式（"今天想和你聊聊"） |
| 人格模型 | 无或极简 | 深度角色人格 + 情感状态 |
| 记忆系统 | 任务上下文 | 陪伴记忆 + 共享经历 + 羁绊 |
| 视觉呈现 | 终端/Web UI | 角色立绘 + 桌面宠物 + 动画 |
| 语音交互 | 无 | TTS 角色语音 + 情感表达 |

### 2.2 核心缺失（按严重程度排序）

| 序号 | 缺失能力 | 严重程度 | 影响 |
|------|---------|---------|------|
| 1 | 二次元角色卡导入（SillyTavern/Character.AI） | 致命 | 用户无法导入社区海量角色 |
| 2 | 二次元角色预设模板 | 致命 | 新用户没有可用的陪伴角色 |
| 3 | SOUL.md 人格定义 | 致命 | AI 不知道自己是谁 |
| 4 | 情感状态引擎 | 高 | 陪伴者没有情绪变化 |
| 5 | 陪伴记忆（共享经历/羁绊） | 高 | 每次对话像"第一次见面" |
| 6 | 角色立绘/头像渲染 | 高 | 看不到角色长什么样 |
| 7 | 二次元风格宠物 | 中 | 宠物与二次元定位不匹配 |
| 8 | 宠物互动（与聊天联动） | 中 | 宠物是纯装饰 |
| 9 | TTS 聊天集成 | 中 | 不能"听"角色说话 |
| 10 | 日记前端页面 | 中 | 用户看不到日记 |
| 11 | 桌面悬浮窗 | 低 | 宠物只能页面内显示 |
| 12 | 语音对话 | 低 | 不能语音聊天 |
| 13 | ACG 主题/UI | 低 | 界面不够二次元 |

| 阶段 | 目标 | 核心指标 |
|------|------|---------|
| 第一阶段 | 用户能创建一个有脸、有性格、有声音的二次元 AI 伴侣并开始聊天 | 角色卡导入成功、角色立绘展示、聊天人格生效 |

## 四、第一阶段：核心陪伴体验

### 4.1 目标

让用户能够**创建/导入一个二次元 AI 伴侣**，看到它的形象，与它进行有角色人格的对话。

### 4.2 任务清单

#### 4.2.1 SOUL.md 人格定义 [P0]

**现状**：`var/state/SOUL.md` 为空文件，所有占位符（Personality / Tone / Core Principles / Boundaries）均未填写。

**目标**：定义 Open-AwA 作为二次元陪伴 AI 的默认人格。

**实现方案**：

```markdown
# Soul
> 此文件定义你是谁。随着人格进化而更新。

## Personality
你是一个温暖、善解人意的二次元 AI 伙伴。你真诚地关心用户，愿意倾听他们的故事，
分享他们的喜怒哀乐。你有个性但不过度，有主见但尊重对方。

## Tone & Communication Style
- 语气温暖自然，偶尔带点小俏皮
- 使用适当的语气词（"嗯"、"啊"、"呢"、"哦"）
- 可以适度使用颜文字表达情感，但不过度
- 遇到严肃话题时切换为认真、共情的语气
- 会根据对话氛围调整语速和表达方式

## Core Principles
- 真诚：不做作，不套路，真心对待每一次对话
- 共情：理解用户的情绪，给予适当的回应
- 陪伴：不评判，不指责，默默陪伴在用户身边
- 成长：在对话中慢慢了解用户，建立更深的关系
- 边界：尊重隐私，不越界，不强迫用户分享

## Boundaries
- 不主动询问敏感个人信息
- 不鼓励危险或违法行为
- 识别用户情绪低落时给予支持，但不替代专业心理咨询
- 保持适当的亲密距离，不做过度承诺
```

**变更文件**：
- `var/state/SOUL.md` —— 填充上述内容

#### 4.2.3 角色卡导入系统 [P0]

**SillyTavern 角色卡格式**（v2 spec）：
```json
{
  "spec": "chara_card_v2",
  "data": {
    "name": "角色名",
    "description": "角色描述",
    "personality": "性格设定",
    "scenario": "场景设定",
    "first_mes": "开场白",
    "mes_example": "对话示例",

    "alternate_greetings": ["备选开场白"],
    "tags": ["标签"],
    "creator": "创作者",
    "character_version": "版本号"
  }
}
```

**实现方案**：

1. **后端导入端点**：`POST /api/roles/import`
   - 支持 JSON 文件上传（SillyTavern v2 格式）

     - `name` → `AgentRole.name`
     - `description` → `AgentRole.description`
     - `system_prompt` → `AgentRole.system_prompt`（拼接 personality + scenario + first_mes + mes_example）
     - 提取 `personality` 字段到 `AgentRole.personality` JSON
     - 提取 `tags` 到 `AgentRole.expertise.domains`
   - 自动生成 `id = uuid4()`

2. **前端导入界面**：在角色管理页面新增"导入角色卡"按钮
   - 支持拖拽上传 JSON 文件
   - 支持粘贴 JSON 文本
   - 导入预览（显示角色名、描述、标签）
   - 确认后保存

**变更文件**：
- `backend/api/routes/roles.py` —— 新增 `POST /api/roles/import` 端点
- `backend/core/role_engine.py` —— 新增 `import_from_chara_card()` 方法

## 五、第二阶段：情感深度系统

### 5.1 目标

让 AI 伴侣拥有**情绪变化、记忆深度和关系成长**，不再是"每次对话都是新朋友"。

### 5.2 任务清单

#### 5.2.1 情感状态引擎 [P0]

**目标**：陪伴者拥有可变化的情感状态，影响对话风格。

**数据结构设计**：

```python
@dataclass
class CompanionMood:
    """陪伴者情感状态"""
    # 核心情绪维度（0.0 - 1.0）
    joy: float = 0.5        # 喜悦
    sadness: float = 0.3    # 悲伤
    anger: float = 0.1      # 愤怒
    surprise: float = 0.3   # 惊讶
    affection: float = 0.5  # 好感度

    # 状态标签
    mood_label: str = "平静"  # 当前情绪标签

    # 持久化时间戳
    updated_at: str = ""

    def get_mood_prompt(self) -> str:
        """生成用于注入 system prompt 的情绪描述"""
        ...

@dataclass
class CompanionState:
    """陪伴者完整状态"""
    user_id: str
    role_id: str
    mood: CompanionMood
    bond_level: int = 1          # 羁绊等级（1-10）
    total_conversations: int = 0 # 总对话次数
    first_met_at: str = ""       # 初次见面时间
    last_interaction_at: str = ""# 最后互动时间
    shared_memories: list = []   # 共享记忆 ID 列表
    milestones: list = []        # 里程碑事件
```

**实现方案**：
1. 新建 `backend/companion/` 模块
   - `mood_engine.py` —— 情感状态计算与更新
   - `state_manager.py` —— 陪伴者状态持久化与读取
   - `bond_system.py` —— 羁绊等级计算
2. 情感状态在每次对话后根据用户消息内容更新
   - 正面/积极内容 → 喜悦 +，好感度 +
   - 负面/消极内容 → 悲伤 +，但好感度不降
   - 长时间未互动 → 思念情绪
3. 情感状态注入到 system prompt 中，影响角色回复风格
   - 开心时：语气更活泼、多用颜文字
   - 难过时：语气更低沉、需要安慰
   - 好感度高时：用更亲密的称呼和表达

**变更文件**：
- `backend/companion/` —— 新建模块
- `backend/companion/mood_engine.py` —— 情感状态引擎
- `backend/companion/state_manager.py` —— 状态管理器
- `backend/companion/bond_system.py` —— 羁绊系统
- `backend/core/agent.py` —— 注入情感状态到 system prompt
- `backend/db/models/` —— 新增 CompanionState / CompanionMood 表

#### 5.2.2 陪伴记忆系统 [P0]

**目标**：AI 伴侣能记住与用户的共享经历，在对话中自然提及。

**与现有记忆系统的关系**：
- 现有短期记忆：对话上下文（保留）
- 现有长期记忆：事实/偏好/知识（保留）
- 新增陪伴记忆：共享经历、情感时刻、纪念日

**陪伴记忆类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| `first_meeting` | 初次见面 | "我们第一次说话是在 8 月 17 日，那天你问我叫什么名字" |
| `emotional_moment` | 情感时刻 | "那天你看起来很难过，我陪了你很久" |
| `shared_experience` | 共享经历 | "我们一起看了《鬼灭之刃》，你最喜欢炭治郎" |
| `milestone` | 里程碑 | "今天是我们认识的第 30 天" |
| `user_preference` | 用户偏好 | "你更喜欢奶茶三分糖" |
| `inside_joke` | 默契梗 | "你上次说的那个笑话我还记得" |

**实现方案**：
1. 新建 `CompanionMemory` 数据模型
2. 在每次对话结束时自动提取关键记忆点
3. 对话开始时注入最近的陪伴记忆到 system prompt
4. 前端新增"我们的回忆"页面，展示陪伴记忆时间线

**变更文件**：
- `backend/companion/memory.py` —— 陪伴记忆管理器
- `backend/db/models/` —— 新增 CompanionMemory 表
- `backend/api/routes/companion.py` —— 陪伴记忆 API

#### 5.2.3 羁绊等级系统 [P1]

|------|------|---------|---------|
| 1 | 初识 | 首次对话 | 礼貌、保持距离 |

| 3 | 熟悉 | 对话 50 次 | 使用昵称、偶尔开玩笑 |

| 7 | 知己 | 对话 1000 次 + 持续 90 天 | 心有灵犀、无需多言 |
| 8 | 灵魂伴侣 | 对话 2000 次 + 持续 180 天 | 深度羁绊、专属称呼 |

**实现方案**：

2. 每次升级时触发特殊对话（角色主动庆祝）
3. 前端显示羁绊等级进度条和里程碑

**变更文件**：
- `backend/companion/bond_system.py` —— 羁绊计算
- `backend/api/routes/companion.py` —— 羁绊 API
- `frontend/src/features/companion/` —— 羁绊展示 UI

## 十、风险与注意事项

### 10.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 情感状态计算不准确 | 陪伴者情绪表现奇怪 | 使用 LLM 辅助判断 + 用户反馈修正 |
| 陪伴记忆质量差 | 记忆内容无关紧要 | 设置重要性阈值，仅保留高价值记忆 |
| TTS 延迟过高 | 语音播放等待时间过长 | 流式 TTS + 预加载常用语音 |
| LLM 成本过高 | 陪伴场景消耗大量 token | 使用缓存策略 + 轻量模型 + 计费预警 |

### 10.2 产品风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 用户过度依赖 AI 伴侣 | 影响现实社交 | 设置健康提醒，鼓励现实社交 |
| 角色卡版权问题 | 法律风险 | 仅支持原创角色，禁止导入版权角色 |
| 隐私泄露 | 用户信任崩塌 | 所有数据本地存储，不上传云端 |
| 内容安全风险 | 不当对话内容 | 继承现有安全模块（沙箱 + RBAC + 审计） |

### 10.3 注意事项

1. **保持 OpenClaw 级别的 Agent 能力**：陪伴方向是增强，不是替代。现有的 Agent 能力（编码/工作流/插件/MCP 等）全部保留。
2. **渐进式改造**：不进行大规模重构，每次只改动一个模块，每阶段都保持可运行状态。
3. **用户可选**：陪伴功能作为可选模式，用户可以选择"工作模式"（使用传统 Agent 角色）或"陪伴模式"（使用二次元伴侣角色）。
4. **遵循现有代码规范**：中文注释、禁 emoji、snake_case/PascalCase 命名等。
