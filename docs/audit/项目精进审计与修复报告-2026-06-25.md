## 二、Desktop 模块（最紧急）

桌面应用为本次新开发模块，问题密度最高，含多个阻断性 bug。

### 2.1 P0 问题

#### P0-1 preload 与 sandbox 不兼容（运行时崩溃）
- 位置：`desktop/src/preload/index.ts:7`、`desktop/src/shared/config-store.ts:5`
- 现象：preload 顶层 `import { getBackendUrl } from '../shared/config-store'`，而 config-store 依赖 `electron-store`（依赖 Node `fs`）。主窗口 `sandbox: true`，沙箱 preload 下 `fs` 不可用。
- 后果：preload 崩溃，`__OPENAWA_BACKEND__` / `__OPENAWA_DESKTOP__` 注入失败，渲染进程拿不到任何桌面 API。
- 修复方案：preload 不再直接读 store，改为通过 `ipcRenderer.invoke(IPC_CHANNELS.BACKEND_GET_URL)` 向主进程取值；初始值仅注入 `version`/`platform`/`isPackaged` 等静态信息，`url` 由渲染进程运行时拉取。

#### P0-2 生产环境前端加载路径错误（白屏）
- 位置：`desktop/src/main/window.ts:86`、`desktop/scripts/build-frontend.ts`
- 现象：window.ts 加载 `resources/frontend/dist/index.html`，但 build 脚本把 `frontend/dist` 内容复制到 `resources/frontend`，无 `dist` 子目录。
- 修复方案：统一为 `resources/frontend/index.html`，window.ts 与 build 脚本保持一致。

#### P0-3 图标缺失（构建失败/无托盘）
- 位置：`desktop/src/main/tray.ts:17`、`desktop/electron-builder.yml`
- 现象：引用 `resources/icons/tray.png`、`resources/icons/icon.png`，但目录不存在。
- 修复方案：tray.ts 增加路径存在性检查，缺失时回退 `nativeImage.createEmpty()` 并记录 warning（不再静默）；electron-builder.yml 增加图标缺失容错说明；本次不生成二进制图标资源（需用户提供），但代码层面保证缺失时不崩溃。

#### P0-4 窗口最大化监听器时序错误（永不注册）
- 位置：`desktop/src/main/ipc/window.ts:52-60`
- 现象：`registerWindowIpcHandlers` 在窗口创建前调用，`getMainWindow()` 返回 null，监听器未绑定。
- 修复方案：将窗口事件桥接逻辑抽离为 `attachWindowEventBridge(win)`，在 `createMainWindow` 内窗口创建后立即调用。

#### P0-5 窗口关闭后引用未清空（后续调用崩溃）
- 位置：`desktop/src/main/window.ts`
- 现象：监听 `close` 但未监听 `closed` 置空 `mainWindow`，托盘/快捷键调用已销毁窗口抛 "Object has been destroyed"。
- 修复方案：增加 `closed` 监听器置空 `mainWindow` 引用。

#### P0-6 ESLint 9 配置失效（CI 门禁形同虚设）
- 位置：`desktop/eslint.config.js`、`desktop/package.json`
- 现象：装的 ESLint 9（强制 flat config），配置却是 ESLint 8 旧式 CommonJS，且 `@typescript-eslint/parser` 未在 devDeps，`--ext` 在 ESLint 9 已移除。
- 修复方案：重写为 flat config，补齐 devDeps，更新 lint 脚本。

#### P0-7 引导窗口关闭所有安全隔离（RCE 风险）
- 位置：`desktop/src/main/index.ts:90-93`、`desktop/resources/onboarding.html:101`
- 现象：`contextIsolation: false, nodeIntegration: true`，onboarding.html 直接 `require('electron')`。
- 修复方案：改为 `contextIsolation: true, nodeIntegration: false, sandbox: true`，引入独立 onboarding preload，通过 contextBridge 暴露白名单 API。

#### P0-8 IPC 最大化广播与窗口事件重复且分散
- 位置：`desktop/src/main/window.ts:63-64` 与 `desktop/src/main/ipc/window.ts:54-59`
- 现象：两处都注册 maximize/unmaximize 监听器，职责重叠。
- 修复方案：合并到 `attachWindowEventBridge`，统一一处管理。

## 三、Backend 模块

### 3.1 P0 问题

#### P0-1 SECRET_KEY 硬编码默认值
- 位置：`backend/config/settings.py:99`
- 现象：`SECRET_KEY: str = "openawa-dev-default"`，生产环境不配 env 即用此可预测密钥，JWT 可被伪造。AGENTS.md 声称"自动生成"但实际硬编码。
- 修复方案：开发环境保留默认值并打 warning；生产环境（`is_production_environment`）若未显式配置则用 `secrets.token_urlsafe(64)` 生成一次性密钥并记录 CRITICAL 日志警告重启后失效。

#### P0-2 workflow/engine.py eval 使用
- 位置：`backend/workflow/engine.py:533`
- 现象：`eval(compiled, {"__builtins__": safe_builtins}, safe_locals)`，虽限制 builtins 但存在类型逃逸风险。
- 修复方案：本次审查 safe_builtins 实现，确认未暴露 `__class__`/`__subclasses__` 等逃逸路径；补充注释说明安全边界。完整替换为 AST 求值器属较大重构，列入后续路线图。

#### P0-3 migrate_db.py SQL 拼接
- 位置：`backend/migrate_db.py:208,233`
- 现象：f-string 拼 `PRAGMA`/`ALTER TABLE`，虽有验证器但模式危险。
- 修复方案：PRAGMA 不支持参数化，维持白名单映射并补充注释；ALTER TABLE 已有 validate_column_name/validate_column_type 校验，补充单元测试覆盖验证器。
