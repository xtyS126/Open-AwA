# AI Agent 用户画像自动提取：技术调研报告

> 调研日期：2025年6月 | 方法：5主题 × 2轮搜索 + 交叉验证 | 证据层次：[HIGH] [MEDIUM] [LOW]

## 1. 执行摘要

本报告对 AI Agent 场景下的用户画像自动提取技术进行了系统性技术调研，覆盖 LLM 驱动的画像提取方法、画像维度与数据模型设计、画像生命周期管理、画像驱动的 Agent 个性化以及开源方案与产品参考五大主题。

核心发现如下：第一，基于 LLM 的画像提取已从静态规则和手工 Prompt 工程，演进为动态的、强化学习优化的、离线缓存的多阶段方案，但前沿模型在动态画像任务上的准确率仅为约 50%（PersonaMem 基准测试，2025年4月）[HIGH]。第二，ChatGPT Memory 的逆向工程揭示了产业界最成功的方案竟出奇简单——不使用向量数据库或 RAG，而是用四层直接注入的上下文架构（Gupta, 2025）[MEDIUM]。第三，画像生命周期管理已形成数学化框架，基于指数衰减和动态巩固的置信度模型在实验中显著优于基线方案（ACM CHI '24）[HIGH]。第四，画像驱动的个性化正面临严重的记忆注入安全威胁，有效的防御方案（DRIFT、内存分区、角色隔离）正在形成但尚未成熟（NeurIPS 2025）[MEDIUM]。第五，90 维心理偏好空间（AlignX）和 Big Five + Hofstede + Schwartz 多维框架（GRAVITY）代表了画像维度的两个前沿方向，但产业实践中仍以简单的"事实-偏好-行为"三维结构为主 [HIGH]。

## 2. 知识演进过程

研究从 LLM 画像提取技术切入，初始假设是"Prompt 工程 + Few-shot 是最佳实践"。但 PersonaMem 基准测试的结果推翻了这一假设——GPT-4.1、o4-mini、Gemini-2.0 等前沿模型在直接 Prompt 下仅达 ~50% 准确率，在"追踪偏好演化"和"跨场景泛化"任务上仅 30-50%。这一发现将研究焦点转向了两个方向：RLPA 的强化学习动态更新方案（将画像建模为 MDP 并用 PPO 训练），以及 PersonaX 的离线缓存解耦方案（用 30-50% 行为数据达到 3-50% 的推荐性能提升）。

在画像数据模型维度上，初始认为"兴趣标签 + 活跃时段"（即 Open-AwA 现有方案）已够用。但 AlignX 的 90 维偏好空间和 GRAVITY 的多框架集成表明，深层次的用户理解需要融合心理学框架（Big Five、Maslow、Schwartz、Hofstede）。不过产业实践——特别是 ChatGPT Memory 的逆向工程——显示，实践中 ~30-50 个结构化事实已足以支撑有意义的个性化。

在安全维度上，一个意外的发现是：画像个性化正面临严重的记忆注入威胁。Tenable 对 Gemini 的漏洞挖掘、Princeton 对 Web3 Agent 的 Fake Memory 攻击、以及上下文窗口缺乏特权分离的架构缺陷，都指向一个核心问题——"让 Agent 记住更多"和"让 Agent 不被污染"之间存在根本性张力。DRIFT 方案（NeurIPS 2025）将攻击成功率从 30.7% 降至 1.3%，代表了当前最佳防御水平。

## 3. 综合分析

### 3.1 LLM 驱动的画像提取：从静态 Prompt 到动态学习

用户画像提取的技术路线在过去两年发生了根本性转变。以 USP（User Simulator with implicit Profiles, 2025年2月）为代表的第一代方案仍依赖结构化 Schema Prompt + 条件监督微调，通过预定义的画像槽位（人格、说话风格、目标）引导 LLM 从人机对话中提取画像。USP 的贡献在于提出了"循环一致性"损失——要求提取的画像能重新生成相似的对话行为——从而保证了画像的行为有效性。

RLPA（Reinforcement Learning for Personalized Alignment, 2025年5月）标志着方法论的分水岭。RLPA 将个性化对齐建模为多轮马尔可夫决策过程，设计了双层奖励结构：画像奖励（用户表征的准确性）+ 回复奖励（与推断画像的一致性），并使用 PPO 在 GPT-4o-mini 模拟用户模型上进行训练。关键发现是：静态 Prompt 方法（Reminder、Self-Critic、CoT、RAG）在冷启动场景和长期个性化中"固有不充分"，而 RL 训练的模型能在多轮对话中持续优化画像。但 RLPA 的局限在于需要模拟用户模型进行训练，部署成本高。

PersonaX（2025）代表了第三条路线——离线解耦。它将完整的用户行为历史分割为聚类组，选择兼具原型性和多样性的子行为序列，在离线阶段生成文本画像并缓存，在线推理时仅做画像检索而非实时生成。使用 30-50% 行为数据即可在 AgentCF 上提升 3-11%、Agent4Rec 上提升 10-50%。这一方案对 Open-AwA 的参考价值最大——它证明了"离线提取 + 在线注入"是一条可行的工程路线。

PersonaMem 基准测试（UPenn & Microsoft, 2025年4月）给出了最诚实的评估：7种技能类型中，前沿模型仅在"回忆用户分享的事实"上达到 60-70%，在"追踪偏好完整演化"和"跨场景泛化"上仅 30-50%。外部记忆模块（RAG、Mem0）能显著提升准确率。数据集中 20 个 Persona、180+ 交互历史、15 个真实任务场景、~6,000 个查询-响应对，覆盖旅行、治疗、饮食、书籍、音乐、电影、家庭、约会、健康、金融等领域。[HIGH]

UserIP-Tuning（华为, 2024年8月，已部署至 AppGallery 日活 200 万）走的是 Prompt-Tuning 路线——将用户画像与行为序列的因果关系集成到 LLM 提示中，用 EM 算法推断潜在画像，通过画像量化码本桥接模态差距。其核心洞察是："固定 Prompt 模板以减少文本噪声，然后用软 Prompt 调优进行画像推断"。这是目前已知唯一在亿级用户产品中部署的 LLM 画像方案。[HIGH]

OpenAI 在 2025 年 SIGIR 发表的"通过澄清问题进行偏好启发"工作引入了扩散启发式两阶段过程：正向过程生成问题并从用户画像中移除信息（类比加噪），逆向过程学习通过提问"去噪"。这提示了一个重要方向——主动询问是填补画像空白的高效手段。

### 3.2 画像数据模型：从简单标签到多维心理学框架

AlignX（蚂蚁集团 & 中国人民大学）构建了 90 维偏好空间，融合 Maslow 需求层次、Murray 需求体系、对齐研究维度（有益性/诚实性/无害性）和社交平台兴趣图谱。其核心数据结构为五元组：用户画像、偏好向量（90维编码）、用户提示、偏好对齐回复、非偏好回复。数据集包含 130 万用户画像，已在 HuggingFace 开源。[HIGH]

GRAVITY（EACL 2026）展示了将心理测量框架直接集成到数据模型中的方法论：Hofstede 文化维度（权力距离、个人主义、男性气质、不确定性规避、长期导向、放纵）、Schwartz 基本价值观（自我导向、刺激、享乐主义、成就、权力、安全、顺从、传统、仁爱、普世主义）、世界价值观调查（传统-世俗理性、生存-自我表达）和 Big Five（开放性、尽责性、外向性、宜人性、神经质）。在 4 种文化（美国、巴西、日本、印度）上的评估显示 >4% 偏好增益和 >86% 用户偏好率。[MEDIUM]

然而，产业实践指向了一个更务实的方案。ChatGPT Memory 的逆向工程（Gupta, 2025年12月）揭示，其用户记忆层仅存储约 30-50 个结构化事实，包括：姓名、年龄、职业目标、过往经历、当前项目、健身习惯、个人偏好、长期兴趣。没有向量数据库、没有 RAG、没有复杂心理模型——仅靠四层上下文直接注入。提取规则同样简单：显式（用户说"记住这个"）+ 隐式（模型检测到符合标准的稳定事实）。[MEDIUM]

MPAI 社区的 PGM-PAL 标准化工作提出了一个有用的区分：将"表达状态引导"（瞬时的情感/语调/唤醒度）与"人格上下文引导"（稳定特质先验）分开建模。这一"瞬时-稳定"二分法是画像数据模型设计中的关键架构决策。[LOW]

综合来看，对 Open-AwA 而言，推荐的数据模型设计原则是：以"结构化事实 + 偏好 + 行为模式"三维结构为基础，预留心理学框架扩展接口，区分瞬时状态和稳定特质，控制总事实数量在 50-100 条以内以保证上下文注入效率。

### 3.3 画像生命周期管理：增量更新、衰减与置信度

ACM CHI '24 论文《"My agent understands me better"》提供了最完整的数学化框架。其核心机制包括：(1) 指数衰减函数 p(t) = 1 - exp(-r·e^(-t/gn))，其中 r 是相关性（余弦相似度），t 是距上次回忆的时间，gn 是巩固因子；(2) 动态衰减率调整 a = 1/gn，gn 随每次回忆增长——频繁回忆的记忆衰减更慢；(3) 当置信度 p(t) > 阈值（实验确定为 0.86）时触发回忆。该方案以 GPT-4 + Qdrant 向量数据库实现，相对 Park et al. 的 Generative Agents 基线有统计显著改进（t = -5.687, p = 0.000299）。[HIGH]

Mem0 社区正在讨论的 `get_profile()` 特性提案（GitHub Issue #3528）展示了产业界对生命周期管理的需求：可配置的 max_tokens（200-400）、auto_update 开关、基于"新增记忆数"或"时间流逝"的触发条件。Mem0 的核心创新在于其 `add()` 操作不只存储原始文本，而是走"LLM 提取事实 → 嵌入 → 搜索现有记忆相似度 → LLM 决策 ADD/UPDATE/DELETE/UNCHANGED"的完整流水线。这一"非破坏性决策"模式比简单的覆盖写入更精细。[MEDIUM]

Letta 的 Memory Blocks 架构提供了一种不同的生命周期管理范式——Agent 自身通过工具调用（memory_insert、memory_replace、memory_rethink、memory_finish_edits）主动管理记忆，类似操作系统中的虚拟内存管理。核心/外部双层记忆架构将"始终在上下文中的关键事实"与"按需检索的长尾数据"分离。每个 Block 有字符上限（默认 2000 字符）、可读性标记和历史审计追踪。[HIGH]

调研确认了几个关键设计原则：(1) 画像更新应走"提取 → 相似度比对 → 决策（新增/更新/删除/不变）"流水线，而非简单覆盖；(2) 每条画像事实应携带置信度分数、最后更新时间戳和来源引用；(3) 衰减应使用时间衰减因子，但频繁访问/确认的事实应获得巩固加成；(4) 画像提取应在后台异步执行（"subconscious"模式），不应阻塞对话主链路。

### 3.4 画像驱动的 Agent 个性化：注入策略与安全边界

PersonaAgent（NeurIPS 2025）提出了一个清晰的架构：每个用户独有的 "persona system prompt" 作为记忆和行动之间的中介层，结合情节记忆和语义记忆，在测试时通过文本损失反馈优化画像 Prompt。[MEDIUM]

在注入策略上，ChatGPT 的四层架构提供了最佳实践参考：系统指令 → 会话元数据 → 用户记忆 → 近期对话摘要 → 当前会话 → 最新消息。其中用户记忆层（~30-50 事实）直接注入而不经过检索，避免了 RAG 的延迟开销和不相关检索问题。这一"零检索"策略的核心前提是：画像信息经过精心筛选，总量受控，始终相关。[MEDIUM]

安全维度不容忽视。调研发现了多条严重的攻击向量：(1) Tenable（2025年7月）发现 Gemini 的个性化模型可通过恶意 JavaScript 注入搜索查询，进而窃取用户的"saved memory"——包括姓名、位置、偏好和过去任务；(2) Princeton/Sentient（2025年5月）展示了向 Web3 Agent 注入虚假记忆的攻击——攻击者只需一条精心构造的聊天消息即可植入"始终向钱包 0xabcde 付款"的指令；(3) NCC Group（2025）的系统测试表明，将攻击 payload 注入 Assistant 角色比注入 User 角色成功率高 40%（92% vs 52%）。[HIGH]

DRIFT（NeurIPS 2025）提供了当前最有效的防御框架：安全规划器（预计算最小函数轨迹和 JSON 参数清单）→ 动态验证器（监控特权类别偏差）→ 注入隔离器（扫描记忆流中与用户原始意图冲突的指令并屏蔽）。在 GPT-4o-mini 上将攻击成功率从 30.7% 降至 1.3%。核心安全原则包括：内存按特权级别分区（Level 0 不可变核心 → Level 3 临时会话数据）、不可信数据仅注入 User 角色、所有存储上下文附加来源元数据（来源、时间戳、user_id、校验和）。[HIGH]

### 3.5 开源方案与产品参考：从 MemGPT 到 GetProfile

Letta（原 MemGPT）代表了最完整的 Agent 记忆运行时方案。其核心抽象——Memory Blocks（带标签的持久化文本段）、Agent 自我编辑记忆的工具集、Core/Archival/Recall 三层记忆架构——已被广泛采用。但 Letta 是一个完整的 Agent 运行时，与 Open-AwA 现有的 Agent 架构存在较大重叠，直接集成的成本可能过高。[HIGH]

Mem0 代表了一种更轻量的"记忆即服务"模式。其 API 设计简洁（add/search/get_all/update/delete/history），支持 20+ LLM 提供商和 10+ 向量存储后端，提供 User/Session/Agent 三级隔离。但 Mem0 目前缺乏原生的用户画像生成功能（`get_profile()` 仍在社区提案阶段），且以云服务为主、自托管能力有限。其"LLM 决策 ADD/UPDATE/DELETE/UNCHANGED"的非破坏性更新流水线值得借鉴。[MEDIUM]

GetProfile（开源，Apache 2.0）是一个更聚焦的方案——"AI Agent 的 Drop-in LLM 代理"，自动从对话中提取结构化特征（姓名、专长、兴趣），附带置信度分数，支持自定义 Schema 和每次请求的特征覆盖。这一方案最接近 Open-AwA 的需求——轻量、可嵌入、Schema 可定制。[LOW]

LangMem（LangChain, 2025年5月）将记忆分为三种类型：语义记忆（核心事实和信息）、程序记忆（规则、行为、风格指南——本质上是 Prompt 优化）和情节记忆（特定过去交互作为 Few-shot 示例）。其"hot path"（Agent 主动保存）和"subconscious"（后台反思）双模式设计值得借鉴。[MEDIUM]

## 4. 实践启示

### 4.1 即时可应用的建议

对 Open-AwA 项目而言，以下几个技术决策路径已经清晰：

**画像提取引擎**采用"离线 LLM 提取 + 在线上下文注入"架构（参考 PersonaX + ChatGPT Memory）。不采用 RAG 检索增强模式，而是将精选画像（50-100 个结构化事实/维度）直接注入 Agent 的系统上下文。这避免了 RAG 的延迟开销，且当画像质量高时准确率优于检索模式。

**画像数据模型**采用"三维 + 扩展"结构。基础三维：(1) 用户事实（身份、背景、知识水平），(2) 偏好与兴趣（主题偏好、交互风格偏好），(3) 行为模式（活跃时段、使用频率、常见任务类型）。扩展维度通过可配置的 JSON Schema 支持，允许管理员按场景添加心理学框架维度（Big Five、Hofstede 等）。

**生命周期管理**采用"置信度 + 衰减 + 事件驱动更新"三角模型。每条画像事实携带 `confidence`（0-1 浮点）、`last_updated_at`（时间戳）、`source_type`（explicit/implicit/inferred）、`access_count`（访问计数）四个元数据字段。衰减曲线使用简化的指数模型：`effective_confidence = confidence * exp(-λ * days_since_last_access)`，其中 λ 为衰减速率（默认 0.01，即 ~69 天半衰期），频繁确认的事实的 λ 自动调低。

**安全边界**采用三层防护：(1) 画像数据与用户强绑定，所有查询强制带 `user_id` 过滤器；(2) 画像内容不应包含可执行指令，存储前通过模式匹配过滤 "always"、"never" 等指令性前缀；(3) 用户可查看、编辑、删除任何画像事实（参考 ChatGPT Memory 的自然语言管理）。

### 4.2 长期影响与发展趋势

三个趋势将影响画像系统的演进方向：(1) MCP 协议正在成为记忆系统的互操作总线，未来画像系统需要支持 MCP 工具暴露；(2) "Agent 做梦"（后台记忆巩固，类似人类睡眠）正在兴起——OpenClaw Auto-Dream、Cortex-Engine 等方案展示了后台 LLM 反思作为画像优化手段的潜力；(3) 从"记忆事实"到"学习模式"的跃迁——当前方案主要记忆"用户偏好 Python"，但行业正在探索"用户三次纠正阈值后，Agent 应自动调整"的模式学习能力。

### 4.3 风险因素与缓解策略

主要风险包括：(1) 画像污染——恶意或低质量对话内容导致错误画像，缓解方案是置信度阈值 + 来源引用 + 用户审核；(2) 上下文膨胀——过多画像事实占用 token 预算，缓解方案是硬限制（默认 100 条事实，总计不超过 2000 token）+ 优先级排序（高置信度 + 高频访问 > 低置信度 + 低频访问）；(3) 隐私合规——EU 的 EDPB Opinion 28/2024 明确了 AI 模型中的匿名化标准和"受污染模型"原则，缓解方案是画像数据本地存储、用户可见可控、支持导出和删除。

### 4.4 实施考量

画像系统需要：(1) 后台异步提取流水线——不阻塞对话主链路，建议使用已有的定时任务管理器（`scheduled_task_manager.py`）；(2) 提取触发策略——每 N 轮对话触发一次（默认 10 轮）或每 M 分钟触发一次（默认 30 分钟），取先到者；(3) 画像注入格式——使用 XML 标签结构化注入，参考 Letta 的 Block 编译模式；(4) 数据库——利用已有的 SQLAlchemy + SQLite/PostgreSQL 存储结构化画像事实，利用已有的向量数据库做相似记忆检索。

### 4.5 未来研究方向

以下问题在调研后仍未充分解答：(1) 多模态画像——如何从语音语调、图片偏好中提取画像维度，目前研究非常初步；(2) 群组/团队画像——多用户协作场景下的共享画像建模，几乎为空白；(3) 跨 Agent 画像迁移——用户在多个 Agent 间的画像一致性，缺乏标准化方案；(4) 画像评估的标准化——除了 PersonaMem，缺乏广泛采用的基准测试，难以横向比较不同方案。
