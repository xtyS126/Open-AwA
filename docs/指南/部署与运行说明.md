# 部署与运行说明

本文档描述当前仓库在本地开发环境中的启动方式、关键环境变量和部署时需要关注的事项。内容以当前代码实现为准。

## 2. 本地开发部署

### 2.1 启动后端

```powershell
cd d:\代码\Open-AwA\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

或者使用 uvicorn：

```powershell
cd d:\代码\Open-AwA\backend
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

后端会提供：

- `http://127.0.0.1:8000/`
- `http://127.0.0.1:8000/health`

### 2.2 启动前端

```powershell
cd d:\代码\Open-AwA\frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

前端默认地址：

- `http://127.0.0.1:5173`

## 3. 启动时的后端初始化行为

根据当前实现，后端启动时按职责拆分为四个独立步骤：

1. 基础设施初始化：LiteLLM 依赖检测、模型供应商可用性检查、`OPENAWA_API_KEY` 校验（未配置或长度不足 32 字符将拒绝启动）
2. 数据层初始化：DB 建表、计费表、预设角色（RoleEngine）、RBAC 内置角色、Owner 用户创建、默认模型定价与配置
3. 插件系统初始化：市场种子、插件发现、已启用插件加载、`system-tools` 内置插件注册
4. 后台任务初始化：定时任务管理器、微信自动回复、自主运行模式、数据收集器

## 5.1 向量记忆部署注意事项

长期记忆增强能力依赖 ChromaDB 持久化目录和嵌入提供方配置。部署时建议确认：

- 应用进程对 `VECTOR_DB_PATH` 拥有读写权限
- 如使用容器部署，应为向量目录单独挂载持久卷
- 如使用 `sentence-transformers`，镜像或运行环境中需要预装对应依赖
- 如使用 `openai` 嵌入，需评估外部 API 延迟和成本

## 5.2 工作流与工具部署注意事项

工作流能力会调用文件管理、终端执行、网页搜索等内置工具。部署时建议：

- 明确文件工具的允许目录范围，避免暴露整个宿主机文件系统
- 终端执行能力仅在受控环境中启用，并结合沙箱或容器隔离
- 对工作流执行记录和工具调用日志进行保留，便于审计与回溯

## 11. 多语言 LSP 服务器（multilspy）

后端 `core/coding/lsp_proxy.py` 通过 [multilspy](https://github.com/microsoft/multilspy)（Microsoft 开源）统一管理多语言 LSP 客户端，提供 hover / 跳转到定义 / 引用查找 / 补全等能力，覆盖 Python / TypeScript / JavaScript / Rust / Go 等语言。multilspy 会按需自动下载部分语言 server 的二进制，但仍有部分 server 依赖宿主环境的运行时（Node.js / Go / Rust 工具链等）。

各语言 LSP server 与运行时依赖如下：

| 语言 | multilspy 使用的 Language Server | 运行时依赖 | 是否自动下载 |
| --- | --- | --- | --- |
| Python | jedi-language-server | Python（已具备） | pip 依赖随 multilspy 安装 |
| TypeScript / JavaScript | typescript-language-server | Node.js >= 18.16.0 + npm | 需宿主预装 Node.js，server 二进制由 multilspy 管理 |
| Rust | rust-analyzer | 无独立运行时（单二进制） | multilspy 自动下载 |
| Go | gopls | Go 工具链 | 需宿主预装 Go，建议 `go install golang.org/x/tools/gopls@latest` |
| Java | Eclipse JDTLS | JDK >= 17.0.6 + JAVA_HOME | multilspy 自动下载 |
| Kotlin | kotlin-language-server | JDK | multilspy 自动下载 |
| C# | OmniSharp | .NET 运行时 | multilspy 自动下载 |
| Ruby | Solargraph | Ruby | 需 `gem install solargraph` |
| Dart | Dart Language Server | Dart SDK | 需随 Dart SDK 提供 |

### 11.1 本地开发环境安装建议

```powershell
# Python：jedi-language-server 随 multilspy 自动安装，无需额外操作
pip install multilspy

# TypeScript / JavaScript：安装 Node.js 18+ 后
npm install -g typescript typescript-language-server

# Rust：rust-analyzer 由 multilspy 自动下载；如需手动安装
# Windows: scoop install rust-analyzer  或  rustup component add rust-analyzer

# Go：安装 Go 1.20+ 后
go install golang.org/x/tools/gopls@latest
```

### 11.2 CI/CD 镜像构建建议

在 CI/CD 镜像中按需预装目标语言的 LSP server，避免每次启动都触发下载：

```dockerfile
# Python：multilspy 安装即包含 jedi-language-server
RUN pip install multilspy

# TypeScript / JavaScript
RUN apt-get update && apt-get install -y nodejs npm \
    && npm install -g typescript typescript-language-server

# Go
RUN apt-get update && apt-get install -y golang-go \
    && go install golang.org/x/tools/gopls@latest

# Rust（rust-analyzer 由 multilspy 自动下载，可跳过）
# 如需预装：curl -L https://github.com/rust-lang/rust-analyzer/releases/latest/download/rust-analyzer-x86_64-unknown-linux-gnu.gz | gunzip -c > /usr/local/bin/rust-analyzer && chmod +x /usr/local/bin/rust-analyzer
```

### 11.3 LSP 可用性检查

`/api/coding/lsp/diagnostics` 端点通过 `LSPProxy.is_available(language)` 报告语言是否被 multilspy 支持。注意：该检查只校验 multilspy 已安装且语言在支持列表内，不保证运行期 server 二进制一定可启动（实际启动在 `start_server` 时由 multilspy 触发，若 server 缺失会记录日志并返回失败）。生产环境建议按 11.1 / 11.2 预装所需语言的 server。

## 12. Docker 生产部署

本仓库提供完整的 Docker 化生产部署方案，支持 SQLite（默认）与 PostgreSQL（可选）、Let's Encrypt 自动 SSL、健康检查、日志轮转、资源限制等生产特性。

### 12.1 文件结构

| 文件 | 用途 |
| --- | --- |
| `Dockerfile` | 后端镜像（多阶段：前端构建 + Python 运行时） |
| `frontend/Dockerfile` | 前端 Nginx 镜像（多阶段：前端构建 + Nginx 运行时） |
| `docker/entrypoint.sh` | 后端启动入口（密钥校验 + Alembic 迁移 + uvicorn 启动） |
| `docker/nginx/ssl.conf` | Nginx 生产 SSL 配置（HTTP→HTTPS 重定向 + HSTS + CSP） |
| `docker/init-ssl.sh` | Let's Encrypt 证书首次申请脚本 |
| `nginx.conf` | Nginx 基础 HTTP 配置（用于非 SSL 部署） |
| `docker-compose.yml` | 基础服务（backend + 可选 frontend） |
| `docker-compose.prod.yml` | 生产覆盖（资源限制 + SSL + certbot） |
| `docker-compose.postgres.yml` | PostgreSQL 可选覆盖（含 pgbackup 可选 profile） |
| `.env.example` | 环境变量配置模板 |
| `.dockerignore` | 镜像构建排除规则 |

### 12.2 部署前置要求

- Docker Engine >= 24.0
- Docker Compose v2.24+（使用了 `!override` 标签）
- 域名 DNS A 记录已指向部署服务器公网 IP（启用 SSL 时）
- 80/443 端口未被占用（启用 SSL 时）

### 12.3 快速部署流程

#### 步骤 1：准备配置文件

```powershell
cd d:\代码\Open-AwA
cp .env.example .env
# 编辑 .env，至少填写：
#   ENVIRONMENT=production
#   JWT_SECRET_KEY / CSRF_SECRET_KEY / ENCRYPTION_KEY（生产必填，生成方式见 .env.example 注释）
#   DOMAIN（启用 SSL 时填写）
#   EMAIL（启用 SSL 时填写）
#   POSTGRES_PASSWORD（启用 PostgreSQL 时填写）
```

#### 步骤 2：构建镜像

```powershell
docker compose --env-file .env build
```

#### 步骤 3a：开发/测试环境（HTTP，无 SSL）

```powershell
# 仅后端
docker compose --env-file .env up -d

# 启用前端 nginx 反代
docker compose --env-file .env --profile frontend up -d
```

#### 步骤 3b：生产环境（HTTPS + Let's Encrypt）

```powershell
# 1. 首次部署：先申请 SSL 证书
bash docker/init-ssl.sh

# 2. 启动生产服务（自动加载 SSL 配置）
docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env up -d
```

#### 步骤 3c：使用 PostgreSQL（替代默认 SQLite）

```powershell
# 在 .env 中设置 POSTGRES_PASSWORD 后
docker compose -f docker-compose.yml -f docker-compose.postgres.yml --env-file .env up -d

# 同时启用 PostgreSQL 备份（每日自动备份）
docker compose -f docker-compose.yml -f docker-compose.postgres.yml --env-file .env --profile pgbackup up -d
```

#### 步骤 3d：生产 + PostgreSQL 组合

```powershell
docker compose -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.postgres.yml --env-file .env up -d
```

### 12.5 日志与监控

- **容器日志**：每个服务配置 10MB 单文件 + 3-5 个滚动文件
- **后端应用日志**：持久化到 `openawa-logs` 卷（loguru 按大小+时间轮转）
- **Nginx 访问日志**：持久化到 `openawa-frontend-logs` 卷

```powershell
# 查看实时日志
docker compose logs -f backend
docker compose logs -f frontend

# 查看 Nginx 访问日志
docker compose exec frontend cat /var/log/nginx/access.log
```

### 12.8 安全特性

| 特性 | 实现位置 |
| --- | --- |
| 非 root 用户运行 | Dockerfile 中创建 `openawa` 用户（UID 1000） |
| 三密钥独立校验 | `docker/entrypoint.sh` 启动前校验长度 >= 32 |
| Fernet 密钥格式校验 | `docker/entrypoint.sh` 使用 `cryptography.fernet.Fernet` 验证 |
| Alembic 自动迁移 | `docker/entrypoint.sh` 启动前运行 `alembic upgrade head` |
| tini 作为 PID 1 | Dockerfile 使用 `tini` 正确处理信号与僵尸进程 |
| Nginx 限流 | `nginx.conf` 中 `limit_req_zone`（API 10r/s，登录 5r/s） |
| 隐藏 Nginx 版本号 | `nginx.conf` 中 `server_tokens off` |
| HSTS（SSL 模式） | `docker/nginx/ssl.conf` 中 `Strict-Transport-Security` |
| CSP 内容安全策略 | `docker/nginx/ssl.conf` 中 `Content-Security-Policy` |
| WebSocket Origin 校验 | 后端 `validate_ws_origin` + Nginx 反代头 |
| 容器资源限制 | `docker-compose.prod.yml` 中 `deploy.resources.limits` |
| 网络隔离 | `docker-compose.yml` 中 `openawa-net` 自定义网络 |
| 日志轮转 | 所有服务 `logging.options.max-size/max-file` |

### 12.9 故障排查

#### 容器启动失败：密钥校验不通过

```
[FATAL] 生产环境必须显式配置 JWT_SECRET_KEY 环境变量
```

解决方案：在 `.env` 中填写 `JWT_SECRET_KEY`（>= 32 字符），生成方式：
```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

#### Alembic 迁移失败

```
[FATAL] Alembic 迁移失败，容器退出
```

排查步骤：
1. `docker compose logs backend` 查看具体错误
2. 检查 `DATABASE_URL` 是否正确（PostgreSQL 模式下密码是否含特殊字符需 URL 编码）
3. 如需跳过迁移临时启动：`docker compose run --rm backend python -m alembic current` 查看当前版本

#### SSL 证书申请失败

```
Failed authorization procedure
```

排查步骤：
1. 确认 `DOMAIN` 的 DNS A 记录已指向本机公网 IP：`nslookup $DOMAIN`
2. 确认 80 端口可从公网访问（防火墙规则）
3. 确认 `EMAIL` 是有效邮箱

#### 数据卷权限问题

后端镜像使用 UID 1000 的 `openawa` 用户，宿主机卷需匹配权限：
```powershell
# 修复卷权限
docker run --rm -v openawa-data:/data alpine chown -R 1000:1000 /data
```

### 12.10 性能调优建议

- **后端 workers**：默认 1 个 uvicorn worker，多核 CPU 可在 `.env` 中通过 `--workers` 参数提升（但 SQLite 不支持多写并发，需切到 PostgreSQL）
- **Nginx keepalive**：`nginx.conf` 中已配置 `keepalive 32`，可按并发量调整
- **数据库连接池**：`DB_POOL_SIZE` 与 `DB_MAX_OVERFLOW` 环境变量控制
- **Qdrant 向量库**：默认嵌入式模式，大规模数据可切换为独立 Qdrant 服务
