# 后端架构说明

本文档基于当前 `backend/` 目录下的代码，对 Open-AwA 后端的结构、主要模块与数据流做说明。

## 1. 总体结构

后端采用 FastAPI 组织 API 层，通过 SQLAlchemy 管理数据模型，并在 `core/`、`skills/`、`plugins/`、`billing/`、`memory/` 等目录中拆分业务模块。

关键入口：

- [main.py](file:///d:/代码/Open-AwA/backend/main.py#L1-L95)

## 2. 启动入口

`main.py` 负责：

- 创建 FastAPI 应用
- 配置 CORS、CSRF、CSP、速率限制等中间件
- 在 `lifespan` 中按职责拆分为四个独立启动步骤：
  1. 基础设施初始化：LiteLLM 依赖检测、模型供应商可用性检查、`OPENAWA_API_KEY` 校验
  2. 数据层初始化：DB 建表、计费表、预设角色（RoleEngine）、RBAC 内置角色、Owner 用户创建、默认模型定价与配置
  3. 插件系统初始化：市场种子、插件发现、已启用插件加载、`system-tools` 内置插件注册
  4. 后台任务初始化：定时任务管理器、微信自动回复、自主运行模式、数据收集器
- 注册 39 个业务路由模块
- 提供根路由、健康检查、Prometheus 指标路由
- 生产环境下挂载前端 SPA 静态文件

参考：

- [main.py](file:///d:/代码/Open-AwA/backend/main.py#L181-L460)

### 6.1 多轮对话上下文机制

Agent 初始化时会创建 `MemoryManager` 并注入到 `FeedbackLayer`。每次处理请求时：

1. `AIAgent._build_conversation_history()` 从 `ShortTermMemory` 中按 `session_id` 检索最近的对话记录
2. 对话历史注入到 `context["conversation_history"]`
3. `ExecutionLayer._build_messages_with_history()` 将历史消息拼接为 LLM messages 数组
4. `FeedbackLayer.update_memory()` 在请求完成后将当前轮次的 user/assistant 消息存入 `ShortTermMemory`

这套机制同时适用于前端聊天和微信聊天，不同渠道通过不同的 `session_id` 隔离上下文：
- 前端聊天：`session_id` 由前端传入（默认 `"default"`）
- 微信聊天：`session_id` 格式为 `"weixin:auto:{account_id}:{from_user_id}"`

### 8.2 插件生命周期管理

- 安装（POST /plugins）：创建 DB 记录后自动 discover + load
- 卸载（DELETE /plugins/{id}）：先 unload 运行时实例再删除 DB 记录
- 启用/禁用（PUT /plugins/{id}/toggle）：切换 DB 状态后同步 load/unload
- 列表（GET /plugins）：返回 DB 记录并附带运行时加载状态和生命周期状态

## 12. ACP Vibe Coding 集成模块

### 12.1 模块概述

ACP（Agent Client Protocol）是一套用于调用本地 vibe coding 应用的开放协议。Open-AwA 作为 ACP Host，通过子进程方式拉起 Claude Code、Codex、OpenClaw、OpenCode 等 CLI Agent，统一对外暴露会话管理、流式 prompt、权限审批等接口，避免为每个 Agent 单独编写适配层。

ACP 模块位于：

- [acp_host/](file:///d:/代码/Open-AwA/backend/acp_host/)

### 12.2 架构分层

ACP 模块采用六层架构：

| 层 | 文件 | 职责 |
|----|------|------|
| core | `core.py` | 共享数据结构（`ACPAgentConfig`/`ACPConfig`/`SuspendedPermission`）与异常层级（`ACPErrors` 及 4 个子类） |
| client | `client.py` | 托管客户端 `ACPHostedClient`，处理 ACP 协议事件分发、permission 挂起 future 与 assistant 文本增量合并 |
| service | `service.py` | `ACPService` 服务层，管理子进程生命周期、prompt 轮次、模块级单例注册表与 atexit 清理 |
| permissions | `permissions.py` | 权限审批适配器，工具调用解析、路径越权检测、硬阻断黑名单 |
| tool_adapter | `tool_adapter.py` | 工具调用事件渲染（text/tool_call/status/permission/error 五类） |
| agents | `agents/` | 内置 Agent 配置目录，每个 `.py` 文件定义一个 `AGENT_CONFIG` |

### 12.3 数据流

一轮 prompt 的完整流程：

```text
POST /api/acp/sessions/{id}/prompt (body: {prompt})
  -> 路由校验会话归属 (user_id, session_id)
  -> get_acp_service(agent) 获取 service 实例
  -> ACPService.run_turn(chat_id, agent, prompt_blocks, cwd, on_message)
     -> _get_or_create_session: 首次时 spawn_agent_process 拉起子进程 + initialize + new_session
     -> client.start_prompt(on_message) 注册事件回调
     -> conn.prompt(session_id, prompt) 发起 ACP 协议 prompt
     -> _wait_for_prompt_outcome 等待完成或 permission 挂起
  -> 事件回调 on_message 把 ACP 事件转为 SSE 帧（text/tool/status/permission/usage/result）
  -> 客户端断开时 cancel_turn 取消未完成的 prompt
```

### 12.4 Permission 挂起-恢复机制

当 ACP Agent 发起需要用户审批的工具调用时，`ACPHostedClient` 通过 `asyncio.Future` 挂起当前 prompt 任务，并构建 `SuspendedPermission` 载体推送给前端：

1. Agent 触发 `request_permission` 回调
2. `ACPPermissionAdapter.build_suspended_permission` 提取工具名、目标路径、命令、选项等元信息
3. `is_hard_blocked` 检测命令子串是否命中黑名单
4. 命中黑名单：直接返回 `DeniedOutcome`，不进入用户审批流程
5. 未命中：创建 `SuspendedPermission`，通过 SSE `permission` 事件推送给前端
6. 前端用户选择选项后调用 `POST /api/acp/sessions/{id}/permission` body `{option_id}`
7. `ACPService.resume_permission` 通过 `client.resolve_permission(option_id)` 恢复 future
8. prompt 任务继续执行

硬阻断命令子串黑名单（见 `permissions.py`）：

- `rm -rf /`
- `sudo rm -rf`
- `mkfs`
- `dd if=`

### 12.5 进程树清理

会话关闭时通过 `_kill_process_tree` 递归清理子进程：

- 优先使用 `psutil.Process(pid).children(recursive=True)` 遍历子进程并 kill
- psutil 不可用时回退：Windows 用 `taskkill /F /T /PID`，POSIX 用 `os.kill(SIGTERM)`
- 资源清理通过 `AsyncExitStack.aclose()` 统一释放

## 13. 终端 PTY 模块

终端 PTY 模块位于 `backend/core/terminal/`，提供持久的 PTY 会话与 VT100 屏幕仿真，支持断线重连后的屏幕状态恢复。

### 13.1 VT100 仿真器

`vt_screen.py` 实现简化版 VTE 状态机：

- 解析 ANSI/SGR 转义序列
- 维护字符网格（cols x rows）与光标位置
- 维护滚动历史环形缓冲区
- 提供 `feed(data)` 写入、`get_screen()` 返回当前网格快照

### 13.2 PTY 持久会话

`pty_session.py` 的 `PTYSession` 类封装 PTY 进程与 VT 仿真器：

- `write(data)` 写入 stdin
- `resize(cols, rows)` 调整 PTY 大小
- `get_snapshot()` 返回当前屏幕网格快照
- `get_scrollback(limit)` 返回滚动历史

Windows 依赖 `pywinpty`，POSIX 使用标准库 `pty`。

### 13.3 断线重连与屏幕快照恢复

WebSocket 连接 `/terminal/ws/pty/{session_id}` 时自动推送：

1. `scrollback` 消息：滚动历史内容
2. `snapshot` 消息：当前屏幕网格状态
3. `shell_info` 消息：shell 类型

前端收到后用 xterm.js 恢复显示，实现断线重连无感知。指数退避重连策略为 1s → 30s。

## 14. 通知 API 与 Claude Code Hooks 集成

通知 API 位于：

- [notifications.py](file:///d:/代码/Open-AwA/backend/api/routes/notifications.py)

提供三个端点：

- `POST /api/notifications` 发送通知（body: `title`/`body`/`pane_id`/`notification_type`）
- `GET /api/notifications?limit=N` 列出最近 N 条（默认 50，最大 100）
- `GET /api/notifications/stream` SSE 长连接实时推送（30s 心跳）

每用户环形缓冲上限 100 条（`collections.deque(maxlen=100)`），SSE 连接断开时立即移除订阅队列。

### Claude Code Hooks 模板

模板配置位于 `backend/static/claude-code-hooks.json`，可在 Claude Code 的 settings.json 中引用，将工具事件通过 curl 推送到通知 API。

示例命令：

```bash
curl -s -X POST http://127.0.0.1:8000/api/notifications \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $OPENAWA_TOKEN" \
    -d '{"title":"Claude Code Stopped","body":"Task completed","notification_type":"success"}'
```

`$OPENAWA_TOKEN` 需替换为本地用户的有效访问令牌（与登录后获得的 access_token 相同）。

## 15. 文件预览与反向代理

### 15.1 文件预览

`GET /api/coding/preview/file?path=<path>` 按扩展名分发渲染：

| 扩展名 | 渲染策略 |
|--------|----------|
| `.md`/`.markdown` | `markdown` 库渲染为 HTML + `bleach` 净化 |
| `.png`/`.jpg`/`.jpeg`/`.gif`/`.webp`/`.svg` | `StreamingResponse` + 正确 Content-Type |
| `.mp3`/`.wav`/`.mp4`/`.webm`/`.ogg` | `StreamingResponse` + Range 请求支持 |
| `.docx`/`.xlsx`/`.pptx` | 可选依赖 `mammoth`/`openpyxl`/`python-pptx`，缺失降级为下载链接 |
| 文本类 | 返回 `{type:text, content:...}` |
| 其他 | 返回下载链接 |

所有路径通过 `_validate_file_path` 防止路径遍历攻击。

### 15.2 反向代理

`GET /api/preview/{port}/{path:path}` 反向代理到 `http://127.0.0.1:{port}/{path}`，用于在统一域名下访问本地开发服务器（如 Vite 5173、Next 3000）。

SSRF 防护策略：

- 拒绝 `port < 1024` 或 `port > 65535`
- 强制目标主机为 `127.0.0.1`，禁止用户传入
- 透传时丢弃 hop-by-hop 头（connection/keep-alive/transfer-encoding 等）

- [coding.py preview_file](file:///d:/代码/Open-AwA/backend/api/routes/coding.py)
